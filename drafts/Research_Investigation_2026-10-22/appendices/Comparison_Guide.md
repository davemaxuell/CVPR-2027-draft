# How to compare the paper groups

The existing library folders are useful discovery tags. A scientific comparison needs several independent axes: a paper can belong to multiple groups, and two papers sharing one tag may still use incompatible evaluation protocols. The [dossier index](../inventory/Dossier_Index.md) contains the verified technical details; the [original folder browser](../../Paper/Paper_Groups.html) remains a convenient entry point.

**“CE” has two different meanings.** VLN-CE means navigation in continuous environments. CE loss means cross-entropy. A continuous-environment agent can itself use cross-entropy training, so these are separate dimensions.

| Dimension | Questions that make a comparison meaningful | Examples and evidence |
|---|---|---|
| Architecture lineage | Is the policy DUET-derived, recurrent, a graph classifier conditioned on an LLM, or a generative action policy? Which modules are inherited? | [DUET](../dossiers/duet.md), [SkillNav](../dossiers/skillnav.md), and [NaviLLM](../dossiers/navillm.md). SkillNav combines DUET experts with VLM routing; these tags overlap. NaviLLM's inspected navigation path is a graph-action classifier, alongside separate generation tasks. |
| Action and sensing interface | Graph viewpoints or continuous motion? RGB, depth, panoramic views, exact pose, waypoint proposals, or robot proprioception? | [SC²-WM](../dossiers/sc2wm.md) distinguishes panoramic and monocular settings. [NaVILA](../dossiers/navila.md) distinguishes high-level RGB reasoning from the robot's additional low-level sensory inputs. |
| Training objective | Action CE, imitation/DAgger, reinforcement learning, generative token loss, reconstruction, contrastive alignment, or a combination? | [DUET](../dossiers/duet.md), [NavGRPO](../dossiers/navgrpo.md), [WS-MGMap](../dossiers/weakmap.md), and [SC²-WM](../dossiers/sc2wm.md) have materially different objectives. “Uses a VLM” does not determine the policy loss. |
| Additional data | More scenes, more paths, more language per path, targeted skill examples, or additional pretraining? Are data and optimization budgets matched? | [ScaleVLN](../dossiers/scalevln.md), [SRDF](../dossiers/srdf.md), [NavRAG](../dossiers/navrag.md), and [SkillNav](../dossiers/skillnav.md). SkillNav's temporal-data-only control is essential for attributing gains to routing. |
| Future prediction | What is predicted: pixels, features, semantic state, successor features, or actions? Is prediction used during training, test-time decision making, or both? | [BEVBert](../dossiers/bevbert.md), [FantasyVLN](../dossiers/fantasyvln.md), [MonoDream](../dossiers/monodream.md), [NavQ](../dossiers/navq.md), and [SC²-WM](../dossiers/sc2wm.md). Predictive training alone does not establish online lookahead planning. |
| Language use | Full instruction encoding, sub-instruction alignment, rewriting, generated reasoning, or semantic verification? Does a contrast require a different correct action? | [SkillNav](../dossiers/skillnav.md) uses reordered text for routing while its experts receive the original instruction. [AirBERT](../dossiers/airbert.md) includes language corruption controls. Sensitivity to changed text is not itself semantic correctness. |
| Mapping and memory | Metric/topological/semantic map, history cache, imagined state, or persistent experience? Does information survive between episodes? | [GridMM](../dossiers/gridmm.md), [SALI](../dossiers/sali.md), [HAM-VLN](../dossiers/ham_vln.md), and [PolarMem](../dossiers/polarmem.md). The source and lifetime of a memory entry matter as much as its representation. |
| Adaptation and training-free claims | Which pretrained components are frozen? Are parameters updated, memory updated, or feedback collected? Is there target-scene exposure? | [SC²-WM](../dossiers/sc2wm.md) updates parameters; [EvoNav](../dossiers/evonav.md) uses between-episode feedback; [RCM](../dossiers/rcm.md) has a target-environment adaptation setting. AirBERT's one-shot adaptation refers to one-house fine-tuning, not absence of training. |
| Reasoning, stopping and recovery | Does a method change action choice, progress tracking, termination, final endpoint ranking, or physical return? What extra sensing or computation occurs? | [FAST/Tactical Rewind](../dossiers/tacticalrewind.md), [Topological Planning](../dossiers/topologicalplanning.md), and [DUET](../dossiers/duet.md) already implement different stopping/return mechanisms. [AdaNav](../dossiers/adanav.md) selectively invokes reasoning. |
| Evaluation and resource protocol | Success versus route fidelity? Single pass versus search/reranking? Held-out scenes versus repeated exposure? Physical path and all model calls counted? | [RxR](../dossiers/rxr.md), [IVLN](../dossiers/ivln.md), [OVER-NAV](../dossiers/overnav.md), and [AirBERT](../dossiers/airbert.md). Report SR, SPL, route metrics and compute under the same protocol before interpreting a score difference. |

For choosing baselines, first match the task, sensors, action interface, data and exposure protocol. Then vary the mechanism being studied. For finding related ideas, use all relevant tags even when the benchmark differs, and explain which assumptions prevent a direct score comparison. These rules are deductions from the reviewed methods, not a new benchmark result.

See [experimental control rules](Experimental_Control_Rules.md) for the corresponding training, evaluation and leakage controls.
