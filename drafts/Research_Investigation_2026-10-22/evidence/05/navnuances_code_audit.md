# NavNuances evaluation audit shared with assignment 04

Assignment 05 inspected the official source snapshot at commit `57c0a58e89e198178a52f2bad067d8328c5aef9f` from https://github.com/zehao-wang/navnuances, stored under `repositories/04/navnuances`. All files below were read completely; none was imported or executed. This complements direct reading of the supplied paper's PDF pages 12–13. It does not constitute baseline model-code inspection.

Inspected files: `evaluation/eval.py`; `evaluation/evaluators/evaluator_base.py`; `evaluator_DC.py`; `evaluator_LR.py`; `evaluator_NU.py`; `evaluator_RR.py`; `evaluator_VM.py`; `evaluation/utils/math_utils.py`.

**INSPECTED CODE.** Direction Change already computes joint left/right success for matched initial orientation (`evaluator_DC.py:24–56`). Both members must succeed; turnaround cases are excluded from that pair metric. The per-example classifier deduplicates consecutive positions, examines the first nonzero edge, uses the heading cross product for left/right, and an angle above 120 degrees for turnaround (`76–140`). Thus this is an atomic first-action test, not an evaluation of recovery over a long instruction. Exact collinearity takes the non-left branch; whether such candidates occur in the benchmark was not measured.

**INSPECTED CODE.** Landmark Recognition's towards test requires strictly reduced final horizontal distance. Its past test checks whether the object projects onto the straight start-to-final segment and whether the final horizontal object distance is below 3 metres (`evaluator_LR.py:48–69`). These are endpoint geometric rules, not tests of all intermediate route interactions.

**INSPECTED CODE.** Numerical Understanding selects the valid reference whose final viewpoint has minimum geodesic distance to the predicted final viewpoint. It computes coordinate nDTW against that selected reference, compares it strictly against the best negative-reference nDTW, and multiplies that result by endpoint distance at most 3 metres (`evaluator_NU.py:59–78`). The positive route is selected by endpoint proximity, not by maximum positive nDTW. `math_utils.py:12–21` defaults the coordinate nDTW scale to one metre. This deserves replication when reusing the diagnostic; substituting another nDTW implementation changes the metric.

**INSPECTED CODE.** Room Recognition checks the final viewpoint against valid room endpoints or outside the start region and separately records whether any viewpoint satisfied the condition (`evaluator_RR.py:47–74`). Vertical Movement inherits standard path metrics and additionally reports the subset whose annotation has both directions (`evaluator_VM.py:27–54`). The base evaluator uses a strict distance below 3 metres for success (`evaluator_base.py:127–134`), while Numerical Understanding uses at most 3 metres.

**DEDUCTION / validity control.** The loader and category loops iterate submitted predictions rather than requiring complete annotation coverage (`evaluator_base.py:52–75`; category `eval` methods). The direction metric requires the partner of every submitted left/right item but does not itself require every benchmark pair. `eval.py` also does not add a coverage assertion. A new evaluation should separately require the expected complete set of unique instruction IDs. This is a safeguard, not evidence that published results omitted examples. No dataset frequency or benchmark effect was tested.

Consequently, paired direction success and ordinal contrast are existing prior art. A new ordered-obligation recovery study must add explicit off-path history, controlled disturbances, valid alternate continuations and full trajectory accounting; it cannot claim the atomic contrast concept itself as new.
