# Original idea specification

Version inspected: design snapshot **23 October 2026**, with original files hashed in material_inventory.json. This reconstruction preserves the current supplied design, rather than substituting older proposals mentioned by its links.

**Research objective, explicitly stated:** determine whether predicted next observations help a frozen navigation policy choose actions that better follow natural-language instructions in continuous environments. The proposed cause is decision-relevant prediction/scoring error, with instruction progress and real history important to useful action selection. Neither its prevalence nor its causal importance on the chosen small policies is established by supplied CE experiments.

**Task and constraints, explicitly stated:** R2R-CE and RxR-CE, RGB deployment, CE training scenes for newly added data. Three separate locked backbone trials: SmolVLM2-500M, LLaVA-OneVision-0.5B, Qwen3-VL-2B-Instruct. Train each with adapted StreamVLN expert supervision and DAgger; start with LoRA and frozen vision for an 8 GB target; then freeze the navigation policy. These are VLM initializations, not trained interchangeable navigation checkpoints. Exact model revisions are in Backbone_Trials.json. No current request fixes a submission year, track or deadline.

**Intervention, explicitly stated:** enumerate four primitive commands, FORWARD/LEFT/RIGHT/STOP. Predict one next observation for each non-STOP action; STOP uses current features. Score candidates using the original instruction, real policy context, current view, recurrent observed-history memory, action and predicted future. Override the base action only above a development-validated utility margin. Execute one action, observe reality and replan. This changes both candidate evaluation and possibly the original policy's action-chunk schedule, requiring a schedule-only control.

**Representations and flow:** policy token width is 960/896/2048 for the respective documented feature contracts. Project instruction tokens and actual-context final hidden state to width 256. Frozen DINOv2-S/14 at 224 pixels gives 256 patches of width 384, pooled to 64 patches. Eight 256-dimensional recurrent slots update once per real observation. Each candidate has one action summary plus 64 future tokens; two candidate attention blocks read real context and memory. A small MLP produces utility, success and forward-collision outputs. Candidate scores do not interact; rejected imagined states never update persistent real memory. The policy context itself can retain history, so removing explicit scorer memory is not equivalent to removing history.

**World-model comparison, explicitly stated:** DINO-WM transferred dynamics vs newly initialized matched DINO dynamics; NWM transferred CDiT vs newly initialized matched CDiT, retaining the same frozen VAE. DINO features are used directly only if conventions match; CDiT latents are decoded to RGB and reencoded by the shared DINO encoder. Exact dynamics checkpoints/sizes remain open; NWM access was recorded as gated. Only commanded actions, available timing and observed history may condition deployment prediction. Future realized pose and collision outcomes are unavailable.

**Supervision and optimization, explicitly stated:** restore identical simulator roots, policy cache, metric prefixes, action budget and random states. Execute candidate a, then continue a fixed one-action-replanning policy pi_ref to termination on real observations. Label the complete actual trajectory with

`U = 0.70 success + 0.30 whole_path_nDTW - 0.01 remaining_actions/B - 0.02 remaining_forward_collisions/B`.

The frozen-policy value target is `Q_ref(I,h,a)=E[U | force a, then pi_ref]`. Whole-path nDTW includes the prefix; costs count only the remainder; B is the original total budget. STOP terminates immediately. Weights are starting choices, not calibrated preferences or validated optimal values. Training regresses U and adds 0.1-weighted success and forward-only collision BCE. Proposed training uses actual features, mixed actual/predicted features, then predicted features; recurrent prefixes are replayed, with proposed 32-step truncated gradients. Fit one pooled scorer per navigation policy and hold its weights fixed across WM comparisons. Train/dev scene groups are separated; shared R2R/RxR scene IDs stay together.

**Later extension, explicitly unresolved:** usefulness-aware dynamics training that penalizes decision-changing prediction errors. The original does not define a finalized objective for it. The current scorer detaches future features, so it does not presently train a world model through scorer gradients.

**Intended benefit:** better instruction-conditioned choices, not merely plausible pictures. Supplied first pilot: 64 roots from at least eight training episodes, all four branches, actual-next-view and matched no-future controls before larger training. Measure branch regret and full closed-loop navigation separately, and account for full inference cost.

**Established implementation scope:** feature-only scorer, utility arithmetic, configuration and synthetic checks. No supplied CE branch outcomes, trained policy adapters, actual visual feature extraction, WM integration, GPU profile or navigation evaluation. Earlier report/dossier conclusions are context, not current implementation results.

**Team interpretations/additions:** staging the core test on one selected locked policy/WM, formal policy-improvement assumptions, candidate losses, matched-root decision thresholds and all later revisions are review proposals, not original user commitments. Any simplified final core is reported separately; the original specifications and four-family/three-backbone trial registry remain intact.
