## 2. Decision-changing compatibility finding: DINO-WM's default grid

**[Code]** The pinned DINO-WM configuration has `img_size:224`, `num_hist:3`, `concat_dim:1`, DINOv2 `dinov2_vits14` with `x_norm_patchtokens`, and a six-layer predictor. Yet `VWorldModel.__init__` computes `encoder_image_size=(image_size//16)*encoder.patch_size`, so this path encodes at **196 pixels**, producing **14×14=196 patches**, not the proposed 16×16=256. `train.py` independently initializes the predictor with `(img_size//16)^2` patches. The scorer's pooling helper rejects 196 patches, as confirmed in the synthetic contract probe. [Pinned model code, lines 55–61](https://github.com/gaoyuezhou/dino_wm/blob/0a9492fa12044b852ae9e001cc74604b79c8bb0c/models/visual_world_model.py#L55-L61), [training construction, lines 243–265](https://github.com/gaoyuezhou/dino_wm/blob/0a9492fa12044b852ae9e001cc74604b79c8bb0c/train.py#L243-L265), [encoder configuration](https://github.com/gaoyuezhou/dino_wm/blob/0a9492fa12044b852ae9e001cc74604b79c8bb0c/conf/encoder/dino.yaml).

This does **not** prove the eventual transferred checkpoint has that grid: no exact DINO checkpoint/configuration has been chosen or loaded. It proves that the inspected default path does not satisfy the planned identity adapter. The original documents already require compatibility checking; this audit resolves one concrete check rather than asserting a contradiction in their conditional wording.

**[Proposal: preferred interface revision]** If the selected checkpoint uses this default grid, preserve 196-pixel DINO encoding and pool 14×14→7×7 for **all** scorer inputs, including real observations and decoded CDiT RGB. Generalize scorer patch count, fixed 2D positions, input checks, padding length and reshape constants. Candidate tokens become 50 rather than 65; real source length becomes `L+51`, and source-plus-memory becomes `L+59`. The learned parameter count need not change. This is an explicit revision from the original 224/64-patch interface; visual accuracy must be retested.

**[Estimate]** Pooled feature storage falls from 49,152 to 37,632 bytes per FP16 view (23.4% reduction). A candidate self-attention score matrix has 50²/65² = 59.2% as many entries; this is not a measured end-to-end speedup. Preserve the same encoder and interface within each transferred/fresh pair. Do not mix 196-pixel real features with resized synthetic feature grids and call them identical representations.

**[Proposal: alternative]** Retain the original scorer and reconfigure/retrain the WM at 224-pixel encoding. Its learned spatiotemporal positional embedding and causal mask must be adapted (e.g. declared per-frame spatial interpolation and mask rebuilding); simply passing 256 patches is insufficient. With three-frame history, tokens grow 588→768; dense attention pair work scales by about 1.706. Checkpoint-specific action/proprioception widths also matter. [Predictor positional and mask code](https://github.com/gaoyuezhou/dino_wm/blob/0a9492fa12044b852ae9e001cc74604b79c8bb0c/models/vit.py#L101-L118).

The stock predictor additionally allocates its mask with `.to('cuda')` in `Attention.__init__` and uses explicit dense attention. A maintained CE adapter should make this a device-following buffer and may use equivalent SDPA after numerical checks. The DINO RGB decoder is unnecessary for feature-only navigation; remove it from this stage instead of inheriting the stock reconstruction job. These are implementation changes, not evidence of a new research contribution.

## 3. Actor, action, state and privilege contracts

**[Metadata]** Exact pinned backbone configurations confirm hidden widths 960/896/2048. They do not supply navigation weights or verify a compatible streaming feature hook. Their native classes differ: SmolVLM, the released OneVision `LlavaQwenForCausalLM`, and Qwen3VL. OneVision's pinned format needs its proper LLaVA/processor integration; a generic AutoModel drop-in is not established. Model metadata/configurations were fetched without weights in [source_pins.json](../evidence/06/source_pins.json).

**[Code]** StreamVLN's `step()` appends observations/history, creates/generates a response, saves `outputs.sequences` and `past_key_values`, then parses an action sequence. `reset_memory()` also resets model-owned state. Therefore replacing the first action after generation is not just changing an integer: future cache state may already encode the unexecuted chunk. The adapter must discard/rebuild that response and commit the actual action. Start with deterministic prefix replay and bounded observation history; introduce optimized cache reuse only after equivalence checks. [Pinned agent, reset and step](https://github.com/InternRobotics/StreamVLN/blob/e48f6ff7e9201d93aae003e8f64b04c00cec13bc/streamvln/streamvln_agent.py#L86-L290).

Required branch snapshot/replay state is: scene/episode and instruction; simulator pose including sensor state; ordered real observations/actions; original step budget; metric prefix/path/collision totals; simulator/task termination state; Python/NumPy/Torch/CUDA and policy sampling states; all adapter/model memory plus cache; policy/configuration revisions. Pose restoration alone does not restore a task. When opaque clone support is uncertain, reset the same episode and replay the real prefix before every candidate. Verify repeated root RGB, base action, feature context and metrics before collecting labels. Reranking candidates must never mutate persistent memory. The current reference satisfies only the feature-level last property.

| Information | Allowed use | Required guard |
|---|---|---|
| RGB, instruction, actual prior actions, elapsed budget | Actor/WM/scorer online inputs | Reconstruct entirely from real experience |
| Canonical candidate command and configured step/turn size | WM online conditioning | Map names to actual Habitat action IDs; distinguish commanded from realized motion |
| Reference trajectory, goal coordinates, success, collisions, future realized displacement | Branch supervision/evaluation | Separate label schema; never include in model-input batches |
| Actual first-next RGB | WM target and privileged scorer diagnostic | Clearly separate from deployable predicted input |
| Past privileged pose/proprioception | Not part of the stated RGB-only deployment | Replace DINO source-domain proprioception with declared available history/neutral fields, identically in both initialization controls |

**[Code]** NWM's training data constructs action conditioning from measured future local positions/yaw; its inference wrapper consumes that displacement, conditions on relative time, samples VAE latents, denoises, decodes and clips RGB. CE must train/condition on *commanded* action values, including blocked motion, rather than leaking its eventual displacement. Retaining NWM's numeric normalization and `1/128` time scale without a CE mapping is not an adapter. [Dataset action construction](https://github.com/facebookresearch/nwm/blob/3f6cd8e70d6f2d1e2b9684acff510710135f0f41/datasets.py#L129-L159), [inference wrapper](https://github.com/facebookresearch/nwm/blob/3f6cd8e70d6f2d1e2b9684acff510710135f0f41/isolated_nwm_infer.py#L76-L102).

**[Estimate]** FP16 64-patch views cost 48 KiB. Current + three actual next views + twelve predicted next views (four WMs × three movement actions) cost 768 KiB/root, or 48 MiB for 64 roots, excluding prefixes, RGB, text, q, metadata and training tensors. Cache instruction features once per episode; cache real features once per prefix node. Recompute trainable memory under current scorer weights. At width 960, 256 instruction tokens are another 480 KiB/episode. [Reproducible arithmetic](../evidence/06/resource_arithmetic.json).

**[Code/Estimate]** NWM's inspected inference driver defaults to **250 diffusion steps**. Naively running three actions separately means 750 denoiser evaluations plus VAE encoding/three decodes/DINO re-encoding per selected action. Candidate batching changes launch count and peak memory, not the three-candidate work. This is not an 8 GB latency result; choose/validate a smaller denoising budget explicitly. Stock CDiT-S/2 is available in source (depth 12, width 384), but its actual checkpoint runtime has not been measured. [Sampling setup](https://github.com/facebookresearch/nwm/blob/3f6cd8e70d6f2d1e2b9684acff510710135f0f41/isolated_nwm_infer.py#L174-L188), [model sizes](https://github.com/facebookresearch/nwm/blob/3f6cd8e70d6f2d1e2b9684acff510710135f0f41/models.py#L305-L324).

**[Estimate]** The 64-root pilot means 192 movement continuations and 64 immediate STOP branches, not merely 256 image predictions. Wall time is driven by continuation length and actor calls. For illustrative full budget B=500, replay-from-reset gives a loose bound of 256×500=128,000 counted actions across these branches, before repeat seeds/failed runs; actual configurations and early termination determine real cost. ## 7. Cheapest implementation order and release gates

1. **Establish inputs/environment, no large training yet.** Locate/license-access the CE scene/episode assets; pin a working Habitat/configuration version; establish CUDA torch and exact backbone processing. Freeze the three policy and four WM registries. Resolve DINO checkpoint grid/proprioception and NWM access. Gate: one real reset/step/STOP episode and deterministic replay, with no privileged fields in model inputs.
2. **One baseline actor adapter.** Begin with SmolVLM2 for lowest measured metadata weight footprint. Implement instruction cache, current-context hook, single-action execution and actual-action cache commit; use LoRA/frozen vision and bounded windows for later CE training. Gate: trained policy baseline plus one-action/chunk schedule control; exact action-ID and cache-replay equivalence. An untrained VLM cannot stand in for the promised trained frozen policy.
3. **Branch tape pilot.** Collect the specified 64 legal roots across at least eight episodes in the correct scene partition, with original prefix/budget/metrics restored. Record each candidate's measured value and current actor identity. Gate: repeated-root equivalence, useful candidate gaps and nondegenerate outcome coverage. This is a collection/debugging pilot, not sufficient training or paper evidence.
4. **Scorer-only qualification.** Cache real features; fit actual-next and same-capacity no-future controls with prefix memory replay. Gate: held-out actual-future decision benefit and sensible STOP/collision handling. If that fails, pause WM expansion.
5. **One DINO family pair and one objective.** Load compatible transferred dynamics and architecture-matched fresh dynamics; train commanded-action CE prediction. Confirm predicted features help beyond no-future. Only then add one measured action-contrast objective, retaining native loss. Gate: lower held-out actual-label regret and closed-loop improvement, plus prediction correspondence tests.
6. **Remaining recorded WM options and actors.** Add CDiT-S transfer/fresh pair when access/interface/runtime permit; fix a versioned pooled scorer for comparable WM testing. The common comparison must rerun when a model is added. Expand selected configurations to OneVision/Qwen policies; do not reuse policy-specific branch labels as if generated by another frozen continuation.
7. **Actual 8 GB acceptance.** Profile the complete deployed path, including simulator, all caches, three movement futures, decoder/DINO if present, scorer and fallbacks. Record dtype, history/token lengths, image resolution, sampler steps, peak device memory, median/tail latency and navigation metrics. Sequential candidate evaluation/offloading are permissible measured configurations. Keep deployment overrides disabled until episode-level development validation.
